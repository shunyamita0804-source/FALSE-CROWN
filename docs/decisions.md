# 暫定仕様の記録

仕様書に明記がない点、仕様同士が食い違う点について、開発側で暫定的に決めた内容です。
優先順位：ユーザーの確定事項 ＞ 新しい版の仕様書 ＞ v01 ＞ ここでの独自判断。すべて後から変更できます。

## 最重要方針（ユーザー確定）

- 主人公への勝敗補正なし。初日から終局し得る。監獄マッチ最下位は例外なく脱落
- NPC の脱落順・優勝者・同盟・裏切りを固定しない。物語は結果に従って変わる
- 探索・物語・隠しイベントは任意。無視しても大会は進む
- 早期脱落による進行不能は、代替経路で防ぐ（誰かを守る形では防がない）

## UI 素材（2026-11-27）

- D-UI-01：正式 UI 素材は加工しない。枠とボタンは CSS の border-image による 9-slice で、四隅の装飾を保ったまま中央だけを伸ばす。色味を変える filter は正式素材に掛けない（ホバーや無効の表現は、押下・無効の素材と文字の濃さで行う）。
- D-UI-02：上部 HUD の帯は左右の端だけを固定し、中央を横に伸ばして 4 区画（日付と残り時間、現在地、所持ピース、操作ボタン）に使う。
- D-UI-03：1 枚に複数の図柄が並ぶ競技素材（M01 の紋章、行動アイコン、M03 の賛成・反対）は、画像を切り出さず、表示位置をずらして 1 図柄ずつ表示する。
- D-UI-04：演出の帯のうち、文字用の余白があるもの（victory、defeat）は帯の中に、無いもの（elimination、discovery、final）は画像の下に、プログラムで文字を出す。
- D-UI-05：アプリアイコンは正式素材の原寸 1 枚をそのまま指定する。以前の縮小版アイコン（public/icons）は削除した。端末側が必要な大きさで表示する。
- D-UI-06：脱落画面で人物の立ち絵を灰色にする処理は、正式素材の色を変えるためやめた。
- D-UI-07：progress_fill は光沢と下線だけの素材のため、ゲージの色そのものはプログラムで描き、その上に素材を重ねる。

## 歩行と操作（2026-11-27）

- D-WALK-01：フィールドのタップ移動は廃止した。移動は方向キー（PC はキーボードも）だけ。会話と調査は、対象の前で決定ボタンを押す。

## DAY 2 の競技と v10 の取り込み（2026-11-27）

- D-M02-01：M02 の出品順は事前に公開しない。残りの品数だけを公開する。資金と持ち物は常に公開し、入札額は落札が決まった後に全員分を公開する（仕様に明記がないための設計値）。
- D-M02-02：残金得点は v02 の試験値（20 につき 1 点、最大 5 点）を採用。同点は残金の多い方が上位、それも同じなら共通決定戦。
- D-M02-03：交換の提案は 1 回の交換時間につき 1 人 2 回まで（無限に提案できないようにする設計値）。提案の両側に同時にお金を載せることはできない。同意の時点でもう一度、双方が渡せる状態かを確かめる。
- D-P02-01：入力する番号も、暗証番号と同じく数字の重複なしの 3 桁に限る。全金庫が開くか全員が 12 回入力したら終了。同点は副得点なしで共通決定戦。
- D-V10-01：v10 の仕様書を `docs/specs/v10/` に取り込んだ。反映状況は `docs/status.md` の 0-2。
- D-V10-02：BGM は v10 の指定どおり、タイトルを Shiny Tech、生活棟の廊下を Airport Lounge に差し替えた。提供された MP3 を加工せずに収録。個室と生活棟のその他の部屋は、専用曲が決まるまで Coffee_Lounge を流す。旧タイトル曲（Echoed_Art）と旧生活棟曲（Mystery_Detective）は割り当てを外し、収録をやめた。

## 実機の指摘への対応と v11 への移行（2026-11-27、v0.7.0）

- D-V11-00：v11 を旧競技仕様より優先する。旧ルールでの競技の追加実装は止め、実装済みの M01、P01、M02、P02 も v11 の競技に置き換える。段階 A（入力、ウィンドウ、歩行）を v0.7.0 として先に公開し、段階 B（新 DAY 1）へ進む。
- D-UPD-01：端末に古い版が残る問題への対処として、`version.json`（キャッシュ対象外）とビルド識別子を照合し、違えば Service Worker の登録とキャッシュを消して読み込み直す。プレイ中には読み込み直さず、通知だけ出してタイトルへ戻った時に行う。同じ版への入れ替えは 1 回だけ試す。
- D-VIEW-01：iPhone のホーム画面起動の横向きで上の余白が 30pt を超えて伝えられた場合は誤りとみなし 0 にする。画面の高さがそのぶん短い時は画面いっぱいに戻す。実機で確認できていないため、効果がなければ別の方法を試す。
- D-WALK-03：待機画像と歩行画像の基準位置の差は、画像を変えずに描画の原点（頭部中心と足元）と表示倍率（0.96〜1.08）で合わせる。値は `scripts/measure-stand.py` が画像から計測して作る。
- D-WALK-04：歩行 1 コマの距離は 32px のまま（1 マスで 2 コマ進み、止まる時の足の形が揃う）。主人公 4.0、NPC 2.1 マス/秒。
- D-NPC-10：NPC は主人公が向かってくると最長 7 秒立ち止まる。待ち続けないよう 12 秒の間隔を置く。主人公だけを待つ処理だが、勝敗や交渉の判定には影響しない（話しかけやすさのための操作性の調整）。
- D-UI-10：ウィンドウは最前面だけが入力を受ける。背後のウィンドウは操作不可にし、会話コマンドは隠す。
- D-BGM-03：resume 指定の場面は再生位置を覚えて続きから鳴らす。音源ファイルは加工しない。
- D-ASSET-05：UI 素材の 2 回目の納品 85 点は、未受領 69 点と追加の図柄 16 点。差し替えはなかった。競技専用の図柄は v11 の実装時に再利用を判断する。

## v11 段階 B（2026-11-27、v0.8.0）

- **D-V11-01 同時進行のパズルの扱い**：M01 と P01 は全員が同時に解く競技。エンジン上は「1 人 1 ステージにつき 1 回の提出（配置と所要時間）」として扱う。CPU の所要時間は能力値から求めた仮想時間で、処理時間ではない。CPU は見えている盤面とピースの形だけで探索し、生成時の解は参照しない。
- **D-V11-02 CPU の能力差**：能力による探索速度の差を約 1.7 倍に抑え、1 回ごとのぶれを加えた（M01 は標準偏差 0.2、P01 は 0.3）。当初の値では P01 で特定の NPC が参加時の 76% で最下位になり、脱落者が固定に近かったため。調整後も朝比奈 63% と偏りは残る。
- **D-V11-03 盤面の当たり判定**：置いたピースは、ピース自身のマスだけがタップに反応する。外接する四角形の空きマスは下の盤面に届く（空きマスをタップしたのに隣のピースが外れる不具合を、画面操作の確認で見つけて修正）。
- **D-MEDAL-01 救いのメダルの判定**：NPC の 1 位は、救う相手と入れ替える相手への好意、信頼、恩義、敵意、警戒、同盟、救済の約束、性格（忠誠、道徳、野心）から点数を出し、基準を超えた時だけ使う。主人公専用の分岐は置かない。指名された NPC は、相手を強く敵視している時と、親しい人が身代わりになる時（忠誠と道徳が高い場合）に辞退する。
