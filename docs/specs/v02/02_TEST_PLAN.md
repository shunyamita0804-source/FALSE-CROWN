# CC用検収・シミュレーション仕様
## 1. 進行の不変条件
- M01〜M10の開始人数=12〜3、監獄4,4,4,3,3,3,3,2,2,2。メイン順位のみで振分け。P最下位1人のみ脱落。DAY11 M11で勝者1人。
- ピース0でも生存。ピースは情報/交渉/探索のみ、点や勝利、脱落免除を買えない。NPCも同条件。競技内専用資金/駒はピースと混同しない。
- 競技ID・素材名・画面を維持。正式デザイン未到着でも検収可能。

## 2. 共通処理（暫定補完）
- 同時手は全員確定まで秘密。合法手の検証をルール側で行う。期限時は事前に公開した合法デフォルト手。時間切れで同意していない取引は破棄。複数手順の途中セーブで二重実行なし。
- 順位同点は各競技の明示副得点→対象者のみ追加論理問題3問（正解数→回答時間）。問題を全員同条件で出し、NPCの処理時間は実CPU時間ではなく能力に応じた仮想回答時間。プレイヤーのルール表示、ポーズ/バックグラウンドは計時外。再同点の場合は新しい同条件の問題セット、最大3セット。それでも同点なら開始時に全員に公開したシード付き抽選の順位を最後の手段として使用。これは完全同点だけに限定する暫定提案であり、乱数で通常勝敗を決めない。使用率を記録し頻発なら競技改修。
- 最終順位が必要なメイン/監獄/決勝以外は引分可。サブ/裏ゲームの引分は明示した場合を除き勝利報酬なし。隠し報酬は周回中1回、サブ報酬は各日各種1回。隠しゲームの敗北で通常大会の脱落なし。
- 資産と報酬フラグの更新を原子的に実行。NPCも同じ経済ルール。負残高、再読込みによる二重取り、複数取引の競合をテスト。会話/情報の売買では事実ログと信念ログを区別。
- NPCの意思決定は、自分の手札/役職/取得情報/公開状態だけから計算。テストで秘密情報だけ変えて同じ観測なら同じシードの行動が変わらないことを確認。P06/S04等の記憶モデルは非公開盤面を再参照しない。

## 3. 実行手順
1. 35競技それぞれの合法手・遷移・得点・終局・保存復元の単体テスト（境界例を含む）。
2. 競技別のテスト用AIを最低3種類（ランダム合法手、貪欲、先読み/協調/ブラフ等ゲームに合ったもの）作る。本番NPCの人格別AIでも対戦。ランダム合法手だけで品質判定しない。
3. 各対戦型競技は初回1000試合以上を目安に実施、同一シードで座席/先後/役職を入替。必要なら5000以上に増やす。パズルは1000生成問題または固定全問題を検証。隠し/サブの単独問題はAI勝率でなく可解性と報酬・時間を確認。
4. 報告指標：試合数、シード、席/役職別平均順位・勝率/最下位率、戦術別勝率/順位、同点率、追加決定戦率、最大再戦率、平均/最大手数、無得点率、行動分布。ゲームの形式に適合しない指標はN/A。シミュレーションの手数と人間の実時間を分ける。
5. 暫定警戒値：同強度で最下位率の席差が10ポイント超、同点が25%超、最後の抽選使用1%超、単一戦術が複数相手方針に対し勝率を継続的に支配する場合は原因分析。警戒値は合格保証ではなく再調整の目安。多人数の勝率は1/nを基準、勝率の標本誤差も記録。
6. 調整値を一度に全部変更せず、原仕様と改訂を同条件で比較。採用値/根拠/未解決事項をCHANGELOGに記録。重要ルール変更は報告。CCで実装できない範囲や実機未確認は明記。
7. 11日間の通しを複数シードでCPUのみ自動実行、毎日1人脱落、NPC取引・裏切り、セーブ復帰、全ゲームIDへの遷移、全8エンド到達性を確認。プレイヤー向けチュートリアルは原仕様と改訂の差分を反映。

## 4. 今回の限定検証について
check_math.py はPython標準ライブラリのみ。P08の固定相手40320列、S05の固定相手60列、P03の合法ランダム試験（各方式20000試合）、P01の期待値を計算。実装版のAIとは無関係。固定相手列の比較は適応的な相手への万能必勝法を証明しない。M05/M07等は得点式の静的分析。その他は構造と例外ケースのレビュー。全35競技をプレイテスト済みという意味ではない。
